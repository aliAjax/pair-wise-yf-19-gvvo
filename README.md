# hxyfront-62007 植物标本馆跨馆调拨入库台

植物标本馆压制标本的**跨馆调拨入库**前端：来源馆调拨登记 → 整批核验 → 按气候带拆箱入位 → 退回与历史追溯。数据只存浏览器（localStorage），刷新后保留。

## 业务规则

1. **整批核验（拒收）**：一个调拨批次中，任一标本缺调出凭证号、或检疫结论不是“合格”，整批拒收——标本不得进入拆箱队列；来源清单原样保留，仓位不变，拒收原因写入调拨历史。
2. **按气候带拆箱（整次拒绝）**：核验通过的批次按气候带进入对应仓位（热带 / 亚热带 / 温带 / 高山）。目标仓位容量不足，或箱内混入气候带不匹配标本时，整次拒绝——来源清单与仓位均不动，仅记录调拨历史。
3. **退回释放**：退回已接收标本时释放对应柜位，标本标记为“已退回”，调拨历史完整保留。
4. **预置数据只读**：三个来源馆、四个气候仓位及容量为规则常量，界面不可修改。

## 页面

- **入库台**：新调拨登记（多标本录入）、待核验批次执行整批核验、拆箱队列选择目标仓位、已拒收清单留存。
- **仓位记录**：四个气候仓位的容量 / 占用 / 柜位明细，逐份退回并即时释放柜位。
- **鉴定筛选**：按鉴定状态（待鉴定 / 已鉴定 / 存疑待核）、入库环节、关键字筛查。
- **采集地卡**：按采集地点聚合，展示气候带、海拔区间、物种数、上柜进度。
- **调拨历史**：登记 / 核验 / 拒收 / 入位 / 退回全量事件流水。
- **标本详情**（右侧抽屉）：完整采集与调拨字段、鉴定结论更新、退回操作、调拨轨迹。

## 分层结构（规则 / 状态 / 页面分开）

```
src/
├── rules/               # 纯领域层，无 React
│   ├── types.ts         # 领域模型
│   ├── constants.ts     # 三个来源馆、四个气候仓位、标签常量
│   └── transfer.ts      # 纯函数：整批核验、容量与气候带判定、单号生成
├── state/               # 状态层
│   ├── reducer.ts       # 所有状态变更入口（不可变更新）
│   ├── selectors.ts     # 派生数据（占用、队列、采集地聚合）
│   ├── seed.ts          # 预置演示数据
│   └── store.tsx        # Context + localStorage 持久化
├── components/          # 页面共用组件（弹窗、抽屉、标本行、徽标）
├── pages/               # 五个页面
└── App.tsx              # 标签页骨架与跨页同步
```

## 预置演示数据

- 3 个历史批次 15 份已上柜（热带 4/8，其中 1 份已退回；亚热带 4/8；温带 6/8；高山 5/6）。
- `B2409-04` 版纳馆热带 4 份已核验待拆箱：入位后热带柜 8/8。
- `B2409-05` 长白山馆高山 3 份已核验待拆箱：高山柜仅剩 1 位，拆箱即容量不足整次拒收。
- `B2409-06` 庐山馆 3 份待核验：1 份缺凭证、1 份检疫不合格、1 份缺凭证号——核验即整批拒收。

页面右上角“恢复预置数据”可随时重置。
