# 植物标本馆跨馆调拨入库台

植物标本馆压制标本的跨馆调拨接收前端。三个来源馆向本馆调出标本，按气候带拆箱入四个气候仓位；规则、状态、页面三层分离，数据仅存浏览器（localStorage），刷新后保留。

## 业务规则

1. **调出资料关（登记时）**：逐份核验「调出凭证编号」与「检疫结论」，**任一标本缺失即整批拒收**——不生成批次、来源清单不动，只在调拨历史留痕。
2. **拆箱接收入库关（接收时）**：按箱面标注气候带拆入对应仓位。
   - 箱内任一标本实际气候带与箱面签不匹配（混装）→ **整次拒绝**；
   - 同气候带总份数超过目标仓位剩余容量 → **整次拒绝**；
   - 任一失败，来源清单与仓位均不改动。
3. **退回**：已上柜标本可退回来源馆，仓位容量立即释放，调拨历史完整保留；退回后可在详情页补正凭证/检疫并重新登记。
4. 所有动作只追加历史事件，不删除。

## 功能页

- **调拨登记**：选来源馆 → 勾选标本（可改箱面气候带签以演示混装拒收）→ 自动生成装箱单 → 提交触发资料关。
- **入库队列**：待接收批次执行拆箱/撤回；已接收批次展示落位记录；拒收批次列出问题并支持撤回。
- **仓位记录**：四个气候仓位（热带/亚热带/温带/高寒）温湿度、容量进度条、在柜标本与退回操作。
- **采集地卡**：按采集地聚合标本，随全局鉴定筛选同步。
- **调拨历史**：登记、资料关拒收、拆箱入库、拆箱关拒收、撤回、退回、鉴定更新的时间线。
- **标本详情**（hash 路由 `#/specimen/SP-001`，刷新保留）：全部字段、鉴定状态切换、凭证/检疫补录、退回、该标本调拨轨迹。

## 预置数据

- 来源馆 3 个：KUN 昆明、PE 北京、IBSC 华南。
- 气候仓位 4 个：热带 4 份 / 亚热带 4 份 / 温带 4 份 / 高寒 3 份（容量故意偏紧，可演示拒收）。
- 种子标本 20 份、采集地卡 11 张；其中数份缺凭证或缺检疫，数份待鉴定/存疑。
- 页面右上角「重置演示数据」可恢复初始台账。

## 架构（规则 / 状态 / 页面分离）

```
src/
├── types.ts               # 数据类型
├── data/catalog.ts        # 预置来源馆、仓位、采集地、种子标本
├── rules/transfer.ts      # 纯业务规则（无 React、无存储，可单测）
│   ├── checkTransferDocs()    # 规则一：凭证 + 检疫
│   ├── planReceipt()          # 规则二：混装 + 容量（纯预演）
│   └── binOccupancy()/canReturn()...
├── state/store.tsx        # 状态机：登记/接收/撤回/退回/补正 + localStorage 持久化
├── components/            # 徽标、Toast、hash 路由等通用 UI
├── pages/                 # 五个工作台页 + 标本详情
└── App.tsx                # 页签、指标卡、全局鉴定筛选、路由
```

## 本地运行

```bash
npm install
npm run dev      # http://localhost:62007
npm run build    # 类型与产物构建
```

技术栈：React 19 + Vite + TypeScript，无额外运行时依赖。
